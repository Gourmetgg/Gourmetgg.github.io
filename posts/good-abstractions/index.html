a good abstraction leaves a door open

hiding the details without hiding the way out

14 August 20262 min read[ programming ]

An abstraction is a promise that you can think about one thing without thinking about everything underneath it. A function name can stand in for twenty lines. A module can stand in for an implementation.

These promises make programming possible. They also make debugging interesting.

the moment the promise breaks

Eventually something unexpected happens. A request takes too long. A value is missing. An operation that sounded simple has a surprising side effect. At that moment, you need a way to look underneath.

This is why I like abstractions with visible seams: clear inputs, meaningful errors, and a straightforward way to inspect the intermediate result. The normal path can be simple without making the unusual path mysterious.

const result = parseDocument(source);

if (!result.ok) {
  console.log(result.line, result.reason);
}

An error with a line number and a reason is an invitation to investigate. An error that only says “something went wrong” closes the conversation.

simplicity with an exit

The goal is not to expose every detail all the time. That would defeat the purpose. The goal is to make those details available when they become relevant.

A good abstraction is a quiet room with a door. You can stay inside while you work, and leave when you need to understand the rest of the building.
