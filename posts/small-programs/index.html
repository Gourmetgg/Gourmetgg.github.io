in praise of small programs

a little code can make a little room

08 October 20262 min read[ programming, essays ]

A small program has a particular kind of charm. You can hold the whole thing in your head. You know where its input comes from, where its output goes, and what happens in between.

It might rename a folder of photographs. It might turn a reading list into a page. It might answer a question you have been answering by hand for months. Its usefulness is almost embarrassingly specific.

one task, done well

We tend to picture software as a product: a name, a roadmap, a set of features. But some of the nicest software is closer to a tool left on a workbench. It exists because there was a job to do.

Here is a tiny example. Given a list of notes, keep the ones that still have a question in them:

const unfinished = notes.filter(note =>
  note.text.includes('?')
);

unfinished.forEach(note => console.log(note.title));

This is not a system. It is an afternoon's curiosity, made executable. That is enough.

leave room around it

Keeping a program small takes a little restraint. The next feature usually sounds reasonable. Then another does. Soon the tool requires more attention than the task it replaced.

The useful question is not “what else could this do?” but “what can I now stop doing?”

I like programs that return a little time to the day. The best ones finish their work, say something plain, and get out of the way.
